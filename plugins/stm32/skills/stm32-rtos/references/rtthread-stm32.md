# RT-Thread on STM32

RT-Thread comes as Nano (kernel only) and Standard (components, device framework, shell, packages). Many STM32 boards have board support packages in the project. Names and configuration systems change between releases; check the version in use.

## Structure
- Configuration lives in `rtconfig.h`, generated by a menu-based configuration tool; builds commonly use SCons.
- `main` runs as a thread after the kernel starts. Board setup and heap initialization happen in the board support files.
- Drivers are exposed through a device framework: find a device by name, open it, then read, write, or control it. A pin API provides GPIO access.

## Key points
- **Create a thread**: dynamic creation with a name, entry, parameter, stack size in bytes, priority, and time slice, followed by a startup call; static initialization is also available. Priority 0 is the highest; the number of levels is configurable.
- **IPC**: semaphores, mutexes (with priority inheritance), event sets, mailboxes, and message queues.
- **Interrupts**: handlers wrap their body with the kernel's interrupt enter and leave calls so the scheduler can run correctly on exit.
- **Heap**: size and placement are configured in the board files; check the available RAM regions.
- **Console**: configure the console UART in the configuration tool and the board's UART setup.

## Failure modes
| Symptom | Likely cause | Check |
|---|---|---|
| Scheduler misbehaves after an interrupt | Missing interrupt enter and leave calls | Handler wrappers |
| Allocation failures | Heap too small or in the wrong region | Heap configuration, linker script |
| No console output | UART instance or pins not configured for the console | Console settings, pin setup |
| Stack overflow | Stack sizes in bytes too small | Increase, enable stack checking |
